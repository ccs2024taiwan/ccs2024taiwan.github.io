# 把正本搬到 D1

決定日：2026-11-18　決定人：李祐華（秘書長）

目標：資料的正本從 Google 試算表搬到 Cloudflare D1。以後日常作業在管理台做，
不必開試算表，按下去也不用等 Google 啟動那兩秒半。

---

## 一、先講清楚：哪些搬得過去，哪些搬不過去

**搬得過去的是「資料」。** 22 種資料目前全部的正本都在試算表或由程式算出來，
這些都可以變成 D1 自己的資料。

**搬不過去的是「Google 才做得到的事」**，一共四類：

| 做的事 | 現在靠什麼 | 為什麼 Cloudflare 做不到 |
|---|---|---|
| 寄信 | Apps Script 的 MailApp | Worker 沒有寄信能力，要另外買寄信服務，而且換了寄件身分，信容易進垃圾桶 |
| 產生文件 | Google 文件（會議紀錄、憑證黏存單、信封、活動建檔） | Worker 不能做 Google 文件 |
| 存檔案 | Google 雲端硬碟 | 同上 |
| 線上會議室 | Google 日曆與 Meet | 同上 |

所以最終的樣子不是「Google 完全消失」，而是：

- **資料正本：D1。** 新增、修改、刪除、查詢都在管理台。
- **Google 退成工具箱。** 需要寄信、做文件、開會議室的時候，由系統去呼叫它。
  試算表不再是正本，變成匯出與列印用。

這跟你說的「全部搬去 D1」是同一件事，只是把「資料」和「動作」分開講。

---

## 二、一條鐵律

**一種資料只能有一個正本。**

搬家期間最危險的是「兩邊都能改」：你在試算表改了一列，管理台同時也改了同一列，
最後誰覆蓋誰看運氣。所以規則是：

> 一種資料搬完的那一刻，就停掉它的同步，並把試算表那張工作表改名加上「（舊）」。
> 從此那張表只能看，不能改。

一次搬一種，搬完確認沒問題再搬下一種。隨時可以停在中間，不會卡住。

---

## 三、順序

### 第 1 步：Worker 要會寫（做這一步時，什麼都還沒搬）

現在 Worker 只會讀。要先讓它會：

- 新增、修改、刪除一筆（刪除是標記，不是真的消失）
- 照設定庫檢查：必填、型別、不重複
- 照角色決定誰能改（acl）
- 照 `lock_after` 鎖欄位：已經過帳的日記帳不給改、只能沖銷
- 每一次寫入都留痕，改前改後都留著

### 第 2 步：管理台要會編輯

表單直接由設定庫的欄位長出來，不用為每一種資料寫一次畫面。
新增、修改、刪除、必填提示、鎖住的欄位變灰。

做完這兩步，才有本錢搬第一種資料。

### 第 3 步：先搬規則少的（純資料）

搬一種資料不是只改一個設定，要先確認「還有誰在寫這張表」。查過之後：

| 資料 | 還有誰在碰它 | 搬家難度 |
|---|---|---|
| 場地 | 沒有人 | 最簡單，**已於 2026-11-18 搬完** |
| 潛在會員 | 志工不錄取時自動建檔 | **已於 2026-11-18 搬完**（那段改成寫進 D1，附一次性匯入） |
| 廠商資料 | 會員專區的名錄是「本會推薦廠商」＋「會員共用的廠商大表」兩份合起來，後者是別人維護的試算表 | 要先決定共用那張怎麼辦 |
| 器材 | 借用、歸還、逾期提醒、LINE 指令都在寫 | 要一起搬 |
| 工作進度 | 活動建檔讀、LINE 回報進度寫 | **已於 2026-11-18 搬完** |
| 參與紀錄 | 會議出席與活動建檔在寫 | **已於 2026-11-18 搬完** |
| 會議、任務 | 幾乎整套系統都在讀它 | 最後再搬 |

所以順序是：場地 ✓ → 潛在會員 ✓ → 工作進度 ✓ → 參與紀錄 ✓ → 其餘見下表。

### 還沒搬的，以及各自卡在哪

| 資料 | 卡住的原因 | 要先解決什麼 |
|---|---|---|
| 會計科目 | 日記帳工作表用公式 VLOOKUP 查「科目表」。搬走公式就壞 | 日記帳一起搬，或改成不用公式 |
| 日記帳 | 訂單、會費、請款、入會都會自動寫進去；表上還有月報公式 | 這些流程一個一個改完才能搬 |
| 任務 | 另一張表的下拉選單直接讀「任務」A 欄的範圍 | 下拉改成由系統給清單 |
| 會議 | — | **已於 2026-11-19 搬完**（選單改成列出會議讓你挑） |
| 器材 | 借用、歸還、逾期提醒、LINE 指令、會員專區都在讀寫 | 下一個（秘書長 2026-11-19 確認控管表可直接接管） |
| 廠商資料 | 會員專區的名錄是本會推薦＋會員共用大表兩份合起來 | 你要先決定共用那張怎麼處理 |
| 課程活動 | **報名中，刻意不動** | 等這一檔活動結束 |
| 訂單、會費、會員、請款 | 官網隨時有人在用，而且規則多 | 等前面幾項穩定，逐一搬 |

### 第 4 步：再搬有規則的

課程活動、請款單與請款品項、訂單、會費繳納、會員、日記帳、會計科目。

每一種都要先把規則搬到 Worker，例如：

- 訂單確認收款 → 寫日記帳、寫銷售紀錄、扣庫存、寄信
- 入會核准 → 產生會員編號、寫日記帳、寄歡迎信
- 請款撥款 → 簽核鏈、寫日記帳
- 會費入帳 → 延長會籍、寄信

文案的部分已經先做好了，這些信的內容現在都在管理台可以改。

### 第 5 步：Google 變工具箱

Worker 需要寄信或做文件時，呼叫 Apps Script。
同步程式停用，試算表只留匯出與列印。

## 四、搬完之後的差別

| | 現在 | 搬完 |
|---|---|---|
| 看資料 | D1，很快 | 一樣 |
| 改資料 | 開試算表，或管理台繞回 Google（約 10 秒） | 管理台直接改，不到 1 秒 |
| 誰是正本 | 試算表 | D1 |
| 留痕 | 只有按鈕動作有 | 每一次修改都有，改前改後都看得到 |
| 手機 | 試算表很難用 | 管理台的手機版（另外做） |
| 你請假 | 別人要會用試算表 | 給帳號就能用管理台 |

## 四之二、三種權限（2026-11-18 決定）

| 身分 | 誰 | 看得到 | 改得動 |
|---|---|---|---|
| 秘書長 | 〈管理員會員編號〉名單 | 全部 | 全部，含刪除 |
| 理監事 | 〈理監事會員編號〉名單 | 行政中心只剩儀表板與財務三頁（志工請款、日記帳、會計科目） | 什麼都不能改 |
| 志工 | 志工專區登入的人 | 志工專區原本那些，加上個別授權給的 | 只有個別授權給到「可以改」的那幾種；刪除永遠不行 |

個別授權在「系統 → 權限」設定：填志工綽號（或 `*` 代表全體志工）、挑一種資料、選「只能看」或「可以看也可以改」。
給了什麼、收回什麼都會留痕。

手機、地址這類 `privacy=secret` 的欄位：**只有秘書長看得到也改得動**（2026-11-18 決定），
其他任何身分都看不到。目前標成個資的是會員手機與地址、訂單手機與地址、志工手機、潛在會員電話。

---

## 五、要注意的事

1. **會員個資。** 搬到 D1 之後，手機、地址這些 `privacy=secret` 的欄位規矩不變：
   任何 API、任何角色都不回傳。管理台上能不能看、誰能看，要你再拍板一次。
2. **備份。** 正本在 D1 之後，備份就不能再靠 Google 雲端硬碟。
   要做定期匯出（每天一份 JSON 存起來），這件事要跟第 1 步一起做。
3. **表單進來的資料。** 課程報名、入會申請、社區坐一坐現在走 Google 表單。
   搬家後有兩個選擇：表單照舊但改成寫進 D1，或是官網自己的表單。前者改動小。
4. **不要急。** 每搬一種，你要照常上班。搬到一半不能讓你沒辦法做事。
